# Спецификация: WP-04

## Требование FR-03: Список занятий

- **WHEN** `GET /lessons` без фильтров (только пагинация по умолчанию)
- **THEN** 200 `{items, total}`; `items` отсортированы по `starts_at`, затем `id`.
- **WHEN** заданы `instructor_id`, `from`, `to`
- **THEN** в выборку попадают занятия с этим преподавателем и `from ≤ starts_at < to`; `total` отражает полное число совпадений.
- **WHEN** заданы несколько фильтров сразу
- **THEN** они применяются совместно (логическое И).
- **WHEN** `limit` больше 200 или некорректен
- **THEN** 422 `VALIDATION_ERROR`.

## Требование FR-05: Изменение занятия

- **WHEN** `PATCH /lessons/{id}` для занятия в `PLANNED` с валидными полями без hard-нарушений
- **THEN** 200 `{lesson, warnings}`; поля обновлены, статус остаётся `PLANNED`.
- **WHEN** занятие не в статусе `PLANNED`
- **THEN** 409 `LESSON_NOT_EDITABLE`; правила BR и stub не обязательны к вызову.
- **WHEN** занятие не найдено
- **THEN** 404 `NOT_FOUND`.
- **WHEN** после слияния полей нарушено hard-правило (например BR-05)
- **THEN** занятие не меняется; ответ с кодом из таблицы BR.
- **WHEN** срабатывает только soft BR-06 или BR-07
- **THEN** 200, изменения сохранены, в `warnings[]` соответствующий code.

## Краевые случаи

- **WHEN** в проверке конфликтов участвует само изменяемое занятие
- **THEN** оно исключается (`exclude_lesson_id`); конфликт «сам с собой» не возникает.
- **WHEN** в PATCH передано пустое тело
- **THEN** 400/422 по контракту openapi (`minProperties: 1`).
