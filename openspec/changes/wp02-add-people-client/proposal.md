# Предложение: WP-02 Клиент people-stub

## Цель
Реализовать асинхронный HTTP-клиент соседнего сервиса `people-stub` (FR-12, NFR-07): три независимых вызова (профиль преподавателя, окна доступности, аудитория для `IN_PERSON`) выполняются параллельно с таймаутом `STUB_TIMEOUT_MS`; ответы 404/5xx и таймаут мапятся в коды платформы. Обязателен unit-тест async-кейса с фейковым клиентом (без сети).

## Trade-offs и альтернативы
- **Выбранный подход:** `httpx.AsyncClient` + `asyncio.gather`; отдельный модуль клиента без доменных BR и без HTTP-ручек создания занятий.
- **Отвергнуто:** последовательные вызовы заглушки — при `STUB_LATENCY_MS=300` это ~900 мс вместо ~300 мс и ломает NFR-07 / скрытый e2e по `max_in_flight`. Создание/`validate` занятий (WP-03) в этот пакет не входят: клиент только готовит данные для следующих пакетов.
