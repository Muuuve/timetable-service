# Технический дизайн: WP-03

- **Слои:**
  - **Домен:** чистые проверки BR-01…BR-07 (длительность, формат/аудитория, существование сущностей, вместимость, пересечения, нагрузка дня, окна доступности). Касание границ интервалов конфликтом не считать; `CANCELLED`/`RESCHEDULED` в BR-05/BR-06 не участвуют.
  - **Клиент stub (WP-02):** параллельный fetch профиля/availability/(classroom); 404/5xx/таймаут: коды платформы.
  - **API:** `POST /lessons` в транзакции проверяет и INSERT; `POST /lessons/validate` — те же проверки без записи. Hard: HTTP-ошибка (или `violations` в validate для кодов 409); soft: `warnings[]`.
- **Порядок:** сначала локальные BR-01/BR-02 и существование группы; затем stub; затем BR-04…BR-07 по данным БД и stub. При нескольких hard — ответ по первому в таблице BR.
- **Время:** вход ISO 8601 со смещением (без смещения: 422 `VALIDATION_ERROR`); ответ через `to_iso_z`.
