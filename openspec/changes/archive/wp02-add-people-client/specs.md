# Спецификация: WP-02
## Требование FR-12: Клиент people-stub
- **WHEN** клиент запрашивает данные для очного занятия (преподаватель + аудитория)
- **THEN** выполняются три HTTP-вызова к stub: `GET /instructors/{id}`, `GET /instructors/{id}/availability`, `GET /classrooms/{id}` — параллельно, каждый с таймаутом `STUB_TIMEOUT_MS`.
- **WHEN** формат занятия `ONLINE`
- **THEN** вызов `GET /classrooms/{id}` не выполняется; профиль и availability запрашиваются параллельно.
- **WHEN** stub отвечает 404 на профиль или аудиторию
- **THEN** клиент сигнализирует «сущность не найдена» (без создания занятия; HTTP-код операции — в WP-03).
- **WHEN** stub отвечает 5xx
- **THEN** операция, которой нужен ответ, отклоняется как `502 UPSTREAM_UNAVAILABLE`.
- **WHEN** вызов превышает `STUB_TIMEOUT_MS`
- **THEN** операция отклоняется как `504 UPSTREAM_TIMEOUT`.
## Требование NFR-07: Async-кейс
- **WHEN** unit-тест выполняет три вызова с задержкой ~300 мс каждый через параллельный клиент
- **THEN** суммарное время порядка ~300 мс (не ~900 мс); выигрыш воспроизводим командой из README «Async-кейс».
